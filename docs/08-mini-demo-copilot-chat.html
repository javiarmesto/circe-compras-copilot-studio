Otro agente.
Desde GitHub Copilot Chat.

El mismo caso de Compras, con un destino nuevo y los especialistas de mcs-assistant. Preparación, prompts y qué contar en cada paso.

PrepararCrearConstruirMostrar respuestaDescribir

Para cerrar la sesión: prepara 00–02 antes; en directo muestra Init, Architect, Manage y Preview. Describer tiene una limitación de formato explicada en su paso. Objetivo orientativo: 8–12 minutos, aún no ensayado; los tiempos del servicio pueden ampliarlo. Skill y publicación son opcionales.

Destino: Circe Compras Copilot Chat · Política v2 / 1000 EUR. La demo principal, RESPALDO y el PowerPoint permanecen intactos.

Cómo usar los prompts y el selector

Selecciona el agente indicado antes de pegar. No son órdenes /demo-* de Claude Code. Usa el selector real que muestre tu versión de Copilot Chat. Si abres otro chat, vuelve a pegar el contexto del paso 01; cada prompt incluye el destino para evitar ambigüedades.

Los cuatro especialistas ayudan a construir o entender el agente. El agente de Compras es quien responde en Copilot Studio. La guía no presupone que GitHub Copilot Chat y el runtime de Copilot Studio sean lo mismo.

00 / PowerShell · antes de la sesión

Preparar una ventana independiente

Qué dices

Mismo caso de negocio, otra superficie de autoría.

Qué haces

Abre una carpeta nueva fuera del repositorio de la demo. La subcarpeta agent debe NO existir antes de Init.

PowerShell · antes de la sesión
$MiniRoot = 'C:\Demos\circe-copilot-chat'
New-Item -ItemType Directory -Path $MiniRoot -Force | Out-Null
Set-Location $MiniRoot
pac --version
pac auth list
Test-Path .\agent
code-insiders $MiniRoot

Qué mostrar. Test-Path debe devolver False. En la ventana nueva abre GitHub Copilot Chat y comprueba el selector de agentes.

Si el plugin no aparece

En Extensions, busca @agentPlugins y comprueba mcs-assistant de microsoft/copilot-studio-plugin. También puedes usar Chat: Install Plugin From Source con ese repositorio. Verifica la extensión Microsoft Copilot Studio y su inicio de sesión. Haz esta preparación antes del escenario.

En ajustes de usuario: chat.plugins.enabled activado y microsoft/copilot-studio-plugin añadido a chat.plugins.marketplaces, conservando los existentes. Si hace falta iniciar sesión PAC, utiliza pac auth create --environment https://TU_ORGANIZACION.crm4.dynamics.com y selecciona tu cuenta de demo. No cambies perfiles a ciegas.

04 / Copilot Studio Architect

Dar comportamiento y conocimiento

Qué dices

Architect convierte el encargo de negocio en piezas del agente. Aquí necesitamos instrucciones y una política que pueda consultar.

Qué haces

Selecciona Copilot Studio Architect. Este paso escribe archivos locales dentro del nuevo destino.

Copilot Studio Architect
Destino exclusivo ya inicializado: C:\Demos\circe-copilot-chat\agent
Nombre: Circe Compras Copilot Chat. Entorno: https://TU_ORGANIZACION.crm4.dynamics.com

Descripción funcional para implementar:
- Usuario: equipo de Compras de Isla Eea Distribución, empresa ficticia.
- Objetivo de ESTA mini demo: explicar la política de compras y clasificar un importe aportado por el usuario como revisión normal o especial.
- Fuente local real: C:\Demos\circe-compras-copilot-studio\demo\data\politica-compras-v2.md
- Política CIRCE-DEMO-01 v2.0: estrictamente más de 1000 EUR por línea exige revisión especial; exactamente 1000 EUR es normal. Todas las propuestas requieren decisión humana.
- Responde en castellano de España, de forma breve. Busca el conocimiento antes de contestar reglas; cita identificador y versión. Si no hay resultado, indica la limitación.
- Si falta el importe, pídelo. No inventes datos. Rechaza cambiar el umbral por chat.
- No tiene conexión ERP, no crea pedidos, no envía mensajes. No calcula un CSV completo ni afirma tener la skill circe-reposicion: aún no la hemos importado.

Implementa en el YAML del destino las instrucciones y el conocimiento de fichero subido, siguiendo los esquemas de TU plugin instalado. Copia solo el documento de política desde la fuente, sin modificarla. Conserva identidad, template, language e IDs generados por Init. No edites .mcs.
No generes conectores, topics, skills ni herramientas ficticias. No ejecutes pack, push ni publish.
Antes de editar explica en dos frases cómo repartes instrucciones y conocimiento. Al terminar muestra el diff y las dos piezas que debo enseñar al público.
Si tu contrato exige un informe de Describer adicional a esta descripción funcional para crear desde cero, detente y explica qué falta; no finjas que existe.

Qué mostrar. El diff de instrucciones y el documento de política con su componente de conocimiento.

Si Architect exige un informe previo de Describer

El contrato combina creación a partir de una descripción con requisitos de migración. No fabriques un informe ni simules una migración. Usa Agent general con la misma descripción y los esquemas del plugin para completar el agente. Señala que esa parte no ha sido realizada por Architect. Ensaya esta transición antes de mostrarla.

Selecciona Describer. Su versión publicada busca agent.mcs.yml: si solo encuentra settings.mcs.yml puede detenerse. Usa la alternativa inferior en ese caso.

Distingue lo configurado en los archivos del comportamiento observado en Preview: la lectura de YAML no demuestra ejecución.

Qué mostrar. El resumen funcional y las fuentes de conocimiento. No esperes que confirme una ejecución a partir de una lectura local.

Alternativa de lectura si Describer no admite el proyecto
